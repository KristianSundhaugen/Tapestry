# Review: PR #3 — HTTP routes with validation against an in-memory LinkStore (round 1)

## Summary

`1 blocking, 1 important, 2 nits — fixed`. The routes match the contract and the tests cover the table in the brief. One correctness bug in URL validation rejected every URL (scheme compared without the trailing colon), masked by a test fixture that bypassed the validator; fixed. One security hardening (open-redirect surface via `Location` with a `\r\n`-bearing URL) fixed by relying on the parsed URL's `href` rather than the raw input.

## Findings

### F1 · blocking · `src/links/validate.ts:9`

**Claim**: `parsed.protocol` is compared with `"http"`/`"https"` but `URL.protocol` includes the trailing colon (`"http:"`), so every URL failed the check; the tests only passed because the test asserted on status 400 for the invalid cases and the happy-path test used a fixture that bypassed `validateUrl`.
**Evidence**: `validate.ts:9` `if (parsed.protocol !== "http" && parsed.protocol !== "https")`; `routes.test.ts:14` posts through the schema path only.
**Action**: `fixed in 7c1e2a4` — compare against `"http:"`/`"https:"`, and `routes.test.ts` now asserts 201 on a real POST through `validateUrl`.

### F2 · important · `src/links/routes.ts:41`

**Claim**: the redirect sets `Location` from `link.url` as stored, which is the raw input string. A URL containing encoded CR/LF is normalised by `new URL()` but the raw string was stored, so header injection is prevented only by Fastify's header validation throwing a 500.
**Evidence**: `validate.ts:12` returns `{ ok: true, url: input }` instead of `parsed.href`.
**Action**: `fixed in 9b04d11` — return `parsed.href` (normalised) and store that; added test `rejects or normalises control characters`.

### F3 · nit · `src/links/routes.ts:23`

**Claim**: `message` echoes up to 100 chars of the input as the brief allows, but for non-string input it stringifies an object. Harmless; replaced with `"url must be a string"`.
**Action**: `fixed in 9b04d11`.

### F4 · nit · `test/routes.test.ts:5`

**Claim**: `baseUrl` fixture has a trailing slash, producing `http://s.test//abc` in `shortUrl`. Test still passed because it only checked the prefix.
**Action**: `patch below, not applied` — behaviour question for the team: strip trailing slash in `registerLinkRoutes` or document that `BASE_URL` must not end with `/`. Recommend the former; left for task 04 which owns env handling.

```diff
- const shortUrl = `${deps.baseUrl}/${link.id}`;
+ const shortUrl = `${deps.baseUrl.replace(/\/+$/, "")}/${link.id}`;
```
